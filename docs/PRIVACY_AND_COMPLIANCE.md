# 개인정보 · 건강정보 보호 및 법규 검토 (MVP)

> ⚠️ **실제 서비스 전환 전 반드시 전문가(법률·개인정보·의료규제) 검토가 필요합니다.**
> 이 문서는 MVP 개발 단계에서 지키는 기술적 원칙과, 출시 전 검토해야 할 항목을 정리한 것이며 법률 자문이 아닙니다.

## 1. MVP 개발 단계의 기술적 원칙

| 원칙                    | 적용 방법                                                                                                                                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 개인정보 최소수집       | 이름(표시명), 성별, 생년월일, 이메일만 수집. 주민등록번호·주소·전화번호 미수집                                                                                                                         |
| 건강정보 최소수집       | 분석에 사용하는 검진 지표·문진 항목만 수집. 진단명·병력 자유기술 미수집                                                                                                                                |
| API Key 서버측 보관     | `src/server/env.ts`(server-only)로만 접근, `NEXT_PUBLIC_` 금지                                                                                                                                         |
| 환경변수 사용           | 비밀값은 `.env`(git 제외), 배포 시 Vercel 환경변수                                                                                                                                                     |
| 비밀번호 평문 저장 금지 | scrypt 해시(salt 포함)만 저장 (`src/server/auth/password.ts`)                                                                                                                                          |
| 로그 개인정보 금지      | `src/server/logger.ts`에서 민감 키·이메일·전화번호 마스킹, Prisma query 로그 비활성                                                                                                                    |
| URL 노출 금지           | 건강정보는 POST body/Server Action으로만 전송, URL에는 추측 불가능한 ID만 사용                                                                                                                         |
| 테스트 데이터           | 가상 인물만 사용 (`User.isSample`), 실제 개인정보 사용 금지                                                                                                                                            |
| 샘플/실제 데이터 분리   | seed는 개발 DB에서만 실행, `/dev/*` 경로는 production에서 비활성                                                                                                                                       |
| LLM 전송 최소화         | 이름·이메일·생년월일·약 이름은 보내지 않음. 연령대(예: "50대")·성별과 엔진이 만든 영역 상태·근거 문장만 전송 (`src/domain/narrative/input.ts`, 테스트로 검증). LLM 요청·응답 본문은 로그에 남기지 않음 |
| 결과표 사진             | 사용할 때마다 전송 안내 동의. 사진은 판독에만 쓰고 DB·로그에 저장하지 않음. 식별정보는 출력 형식에 없어 돌려받지 않음. 판독 기록은 값 없이 시각·항목 수만 저장 (`docs/CHECKUP_IMPORT.md`)              |
| 삭제권                  | 마이페이지에서 본인 데이터 전체 삭제                                                                                                                                                                   |

## 2. 출시 전 검토 필요 항목

1. **개인정보 보호법**: 건강정보는 민감정보 → 별도 동의, 처리방침 공개, 보관기간·파기 절차, 안전성 확보조치(접근통제·암호화·접속기록).
2. **개인정보 국외이전 / 처리위탁**: LLM API·클라우드(Vercel, DB)가 해외 리전일 경우 고지·동의 요건. 결과표 사진(이름 등 식별정보가 찍힐 수 있음)이 Anthropic(미국)으로 전송되는 점 포함.
3. **외부 검진 데이터 연동**: 건강보험공단·검진기관 연동 시 마이데이터 제도 요건, 제3자 제공 동의, 접근 토큰 암호화 보관.
4. **의료법 / 의료기기법**: 서비스 표현과 기능이 의료행위·의료기기 소프트웨어에 해당하지 않는지 (식약처 웰니스 제품 판단 기준, 비의료 건강관리서비스 가이드라인 검토).
5. **표시·광고**: "진단", "치료", "예방" 등의 표현 사용 제한.
6. **판정 기준값**: 규칙 엔진 임계값의 근거에 대한 의료 전문가 검증.
7. **보안 점검**: 출시 전 취약점 점검, 접근 권한 관리, 백업·사고 대응 절차.

## 3. GLP-1 케어 (환자 앱) 추가 사항

- **항목별 동의** (`src/content/care.ts`, 버전 `care-consent-2026-10-v1`): 서비스 이용(필수) / 담당 의원 공유 / 연구 활용(가명) / 제약사 통계(집계)는 각각 따로 받고, 선택 항목을 거부해도 모든 기능을 쓸 수 있다. 설정 화면에서 언제든 변경.
- **의원 연결**: 등록 QR 카드는 연결 코드를 주소의 `#` 뒤에 담아 서버 로그·요청에 남지 않게 한다. 의원 공유 동의가 없으면 위험 신호는 본인 기록에만 남는다 (의원용 화면은 아직 없음).
- **최소 저장**: 식사 사진·CGM 원본 파일은 저장하지 않는다. 사진은 음식 추정을 위해서만 AI 서비스로 전송되며 사용자가 매번 체크해 동의한다 (하루 20회 제한, `ai_usages`에는 성공 여부만).
- **캘린더 알림(.ics)**: 공유 캘린더에 노출될 수 있어 약 이름·용량을 넣지 않는다.
- **표현**: 약 복용·중단·용량 변경을 권하지 않고 "담당 의사와 상의"로 안내. 케어 문구는 AI 안전 검사와 같은 금지 표현 검사를 단위 테스트로 통과해야 한다 (`tests/unit/glp1.test.ts`).
- **광고 규제·중립성**: 약 목록은 성분 순으로 모든 GLP-1 계열을 나란히 보여주며 특정 제품을 강조하지 않는다. 제품명은 사용자가 자신의 처방을 고르는 목록에만 쓴다.
- **삭제권**: 설정의 "케어 기록 삭제"는 케어 데이터만, 마이페이지의 "내 데이터 삭제"는 케어 데이터를 포함해 모두 삭제한다 (cascade).
- **출시 전 검토**: 디지털의료제품법상 위험 신호 안내가 의료기기 기능에 해당하는지 식약처 사전 상담, CGM 판매·연동 관련 의료기기 판매업 신고, 의원·제약사 관계의 공정경쟁규약·의료법(환자 유인) 검토.
